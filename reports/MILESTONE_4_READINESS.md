| Target | Definition and boundary |
| --- | --- |
| Remaining road arrival | Actual later simulated road-arrival clock minus prediction clock, only for trucks not yet arrived. Unresolved arrival is censored/masked. It is not dock completion. |
| Delivery SLA failure | Later actual simulated delivery completion after its configured deadline, predicted before completion. Unresolved outcomes are explicitly censored, never invented on-time successes. |
| Future operational impact | A NEW authoritative realized impact involving a supported resource ID in the next 300 simulated seconds. Exclude already realized events and record supported codes. This is an association label, not proof of incident-caused cascade. |

Terminal records serve outcome audit, not prediction features. Rule ETA/slack/graph scores are explicit baseline outputs. ## Implementation and frozen evaluation plan

1. Finish source/label audits; restore existing services and record actual database/live state without resetting the fleet.
2. Freeze a new versioned generation/split/evaluation protocol before selecting any model. Use whole fresh seed groups for training, validation, calibration and final assessment; none of 11/22/33/44/55 is final. Keep every policy/intervention/adjacent graph from a seed together. Include held-out disruption combinations and larger resource configurations; final labels are not used for tuning.
3. Add an isolated Java corpus runner around the existing engine, plus one shared read-only `MlFeatureExtractor` for corpus, policy experiments and live inference. Reuse the graph exporter/converter. Preserve original B0–B4 code. Write scenario fingerprints, as-of frames, separate later labels and generation manifests to new paths.
4. Establish distance/speed, rule ETA, slack, persistence and mathematical graph baselines. Train small CPU XGBoost regression/classification and graph-feature ablations; tune only on development groups and calibrate only on calibration groups. Serialize models/schema/scalers/calibration and verify reload predictions.
5. If corpus labels vary and CPU dependencies work, execute a small typed heterogeneous graph model and a history-aware variant with the same graph/features and past-only frames. Otherwise retain a validated pipeline with an explicit incomplete training status. Compare to equivalent-feature XGBoost and graph rules; retain worse results.
6. Add a versioned localhost Python inference service on port 8090 with strict request/schema/network/model validation. Java copies the prediction-time state, applies timeouts, validates finite/compatible responses and returns an explicit deterministic fallback on outages or invalid inference. Models never mutate the engine or approve actions. Show provider/version/calibration/latency and simulated provenance in the dashboard.
7. Diagnose M3 passive decision slots, censored candidate horizons, rank normalization, dock repertoire, trigger eligibility and measured computation using preserved traces. New B5 variants get new identifiers. Use validated learned predictions on the same feasible candidate repertoire and compute/decision bounds as controls, with explicit no-ML/graph/temporal/counterfactual ablations. Live action execution remains a separate frozen, explicitly approved transaction.
8. Evaluate predictors and B0–B5 policies on the frozen fresh final scenarios only after model/policy selection. Record actual paired outcomes, prediction quality, calibration, latency, rollouts, failures/fallback and measurable memory. Do not adapt models or scoring after reading final outcomes. An optional OR-Tools comparison is included only if an honest matched scheduling model is feasible.
9. Run the actual old/new tests and read-only integration/restart checks; preserve original data and reports. Publish measured results, failures, changed-file hashes, reproduction commands and a deployment gap assessment. Declare partial completion if required trained inference/policy checks cannot be achieved. Stop before Milestone 5, autonomous LLM, RL and blockchain.

The learned stage will establish only simulator-domain predictive/decision evidence. Real-world freight accuracy, field cascade prevention and commercial superiority remain unvalidated.
